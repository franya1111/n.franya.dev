## 🛠 Технологічний стек

| Технологія | Призначення | Де використовується |
|------------|-------------|---------------------|
| **PHP 8.2** | Backend-логіка | Всі `.php` файли |
| **Nginx (Alpine)** | Web-сервер | `docker/nginx.conf` |
| **PHP-FPM** | Обробка PHP | `docker/Dockerfile.php` |
| **JSON-файли** | Зберігання даних | `data/*.json` |
| **Vanilla JavaScript** | Інтерактив | `js/main.js`, `admin/assets/admin.js` |
| **CSS3** | Стилізація | `css/style.css`, `admin/assets/admin.css` |
| **HTML5** | Розмітка | `.php` шаблони |
| **Docker + Compose** | Контейнеризація | `docker-compose.yml`, `docker/` |
| **Cloudflare Tunnel** | Доступ до сервера | Налаштовано на сервері |
| **Nginx Proxy Manager** | Reverse proxy | Контейнер `my-test-app-1` |

**БЕЗ бази даних MySQL/PostgreSQL!** Всі дані зберігаються у звичайних `.json` файлах у папці `data/`. Це робить сайт:
- Швидким (читання файлу швидше за SQL-запит)
- Переносимим (просто скопіював папку — отримав копію сайту)
- Простим в адмініструванні (можна відкрити JSON у будь-якому редакторі)
- Безпечним (немає SQL-ін'єкцій, немає з'єднання з БД)

## 🔐 Як влаштована адмінка

**Вхід:** `https://n.franya.dev/admin/`

При першому відкритті — форма первинного налаштування:
- Придумай логін (за замовчуванням `admin`)
- Придумай пароль (мін. 6 символів)
- Підтвердити пароль

Після цього — одразу в дашборд.

### Структура адмінки

| Сторінка | URL | Призначення |
|----------|-----|-------------|
| **Дашборд** | `/admin/` | Статистика + останні 5 заявок |
| **Бронювання** | `/admin/bookings.php` | Всі заявки клієнтів |
| **Категорії та ціни** | `/admin/categories.php` | Редагування 6 категорій |
| **Галерея** | `/admin/gallery.php` | Керування публічною галереєю |
| **Відгуки** | `/admin/reviews.php` | Додавання/видалення відгуків |
| **FAQ** | `/admin/faqs.php` | Питання та відповіді (CRUD) |
| **Налаштування** | `/admin/settings.php` | Контакти, Telegram, тексти, пароль |

### Безпека адмінки

- ✅ Пароль зберігається як **bcrypt-хеш** (не відновлюється навіть якщо файл викрадуть)
- ✅ Сесії PHP (не cookie з паролем)
- ✅ `require_login()` на кожній сторінці адмінки
- ✅ Доступ до `data/` заборонений через Nginx (403)
- ✅ Завантаження фото — тільки через `api/upload.php` з перевіркою авторизації

## 💰 Як редагувати категорії та ціни

1. Зайти в адмінку → **Категорії та ціни**
2. Обрати категорію з табів зверху (Індивідуальна / Весільна / ...)
3. Відкриється форма з 3 секціями:

### 📷 Основне
- **Назва** — назва категорії (напр. «Індивідуальна»)
- **Головне фото** — шлях до зображення. Можна:
  - Ввести вручну (напр. `img/service-individual.jpg` або `uploads/photo_xxx.jpg`)
  - Натиснути **«📤 Завантажити нове»** → обрати файл → фото завантажиться в `uploads/` і шлях автоматично з'явиться в полі
- **Короткий опис** — під заголовком на сторінці категорії
- **Детальний опис** — по одному абзацу на рядок
- **Галерея** — 3+ фото. Можна завантажити кілька одразу (кнопка «📤 Завантажити фото для галереї»)
- **Подарунки** — по одному на рядок (напр. «Постійні клієнти — 10%»)

### 💰 Цінові варіанти
- Кнопка **«+ Додати варіант»** — додає новий блок
- Кнопка **«🗑 Видалити»** в кожному варіанті
- Кількість варіантів — **будь-яка** (рекомендується 2-4)
- Кожен варіант:
  - Фото (з превью + кнопка завантаження)
  - Назва (Мінімальний / Стандартний / Максимум / Преміум / ...)
  - Тривалість (1 година / 2 години / ...)
  - Ціна (2500 грн / 4500 грн / ...)
  - Що входить — по одному пункту на рядок
  - ⭐ Чекбокс «Популярний» — показує золотий бейдж «Популярний» на сайті

### 📋 Додаткові послуги
- Кнопка **«+ Додати послугу»**
- Кожна послуга: назва + опис
- Наприклад: «Фотодрук 10x15» / «Друк фотографій у форматі 10x15 см...»

**Зберегти:** кнопка внизу **«💾 Зберегти категорію»**

## ⭐ Як додати відгук

1. Адмінка → **Відгуки**
2. Форма зверху:
   - **Ім'я клієнта** (напр. «Олена»)
   - **Текст відгуку** (українською чи російською)
3. Кнопка **«+ Додати відгук»**

Відгук одразу з'явиться в каруселі на головній.

**Видалити:** кнопка «🗑 Видалити» біля кожного відгуку.

## 📨 Як працює форма бронювання

### Сценарії

#### 1. З головної сторінки
1. Клієнт відкриває `https://n.franya.dev/`
2. Прокручує до секції «Анкета бронювання»
3. Натискає кнопку «Заповнити анкету»
4. Відкривається `booking.php` (без параметрів)
5. Клієнт сам обирає:
   - Вид зйомки (select)
   - Пакет (select, залежить від виду)
   - Кількість учасників (залежить від виду)
   - Дату, час
   - Спосіб зв'язку (Instagram / Telegram / Телефон)
   - Контактні дані
   - Побажання

#### 2. Зі сторінки категорії
1. Клієнт на `https://n.franya.dev/category.php?id=individual`
2. Натискає «Забронювати цей пакет» під конкретним пакетом
3. Відкривається `booking.php?cat=individual&pkg=2`
4. У формі:
   - **Вид зйомки** = «Індивідуальна» (замкнено 🔒, не можна змінити)
   - **Пакет** = «Максимальний» (замкнено 🔒)
   - Клієнт заповнює тільки: ім'я, кількість, дату, час, спосіб зв'язку, побажання

#### 3. Без конкретного пакета
- `booking.php?cat=individual` — вид замкнено, але пакет можна обрати

### Розрахунок знижки

Якщо клієнт активує чекбокс **«Я постійний клієнт(-ка) 🌸 −10%»**:
1. Бере ціну вибраного пакета
2. Рахує `newPrice = price × 0.9`
3. Показує блок:
   ```
   Пакет · 2 години                    4 500 грн
   Знижка постійного клієнта (−10%)    − 450 грн
   - - - - - - - - - - - - - - - - - 
   До сплати:                          4 050 грн
   ```

### Що відбувається при відправці

1. JS збирає всі поля форми
2. Відправляє POST на `api/booking.php` (JSON)
3. PHP:
   - Зберігає заявку в `data/bookings.json`
   - Якщо налаштований Telegram → відправляє повідомлення через Bot API
   - Якщо налаштований email → відправляє через PHP `mail()`
4. Повертає `{success: true}`
5. JS показує блок «Дякую! 🌸»
6. Форма ховається (без кнопки «заповнити ще раз»)

## 📲 Як налаштувати Telegram-сповіщення

### Крок 1. Створити бота

1. Відкрий [@BotFather](https://t.me/BotFather) в Telegram
2. Відправ команду `/newbot`
3. Введи ім'я бота (напр. «Krasnobaeva Booking Bot»)
4. Введи username (напр. `krasnobaeva_booking_bot`)
5. BotFather поверне **Bot Token** у вигляді:
   ```
   1234567890:ABCdefGHIjklMNOpqrsTUVwxyz
   ```

### Крок 2. Отримати Chat ID

1. Додай свого бота в чат або особисті повідомлення
2. Напиши йому будь-що (напр. «/start»)
3. Відкрий у браузері:
   ```
   https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates
   ```
4. У відповіді знайди рядок:
   ```json
   "chat": {"id": 123456789, ...}
   ```
5. Це і є твій **Chat ID**

### Крок 3. Внести в адмінку

1. Адмінка → **Налаштування** → секція **«Telegram Bot»**
2. Заповни:
   - **Bot Token** — з кроку 1
   - **Chat ID** — з кроку 2
   - ☑ **Увімкнути сповіщення**
3. Кнопка **«💾 Зберегти»**
4. Натисни **«📲 Надіслати тестове повідомлення»**
5. Перевір — в Telegram має прийти повідомлення

Тепер кожна нова заявка з форми буде приходити в Telegram з:
```

Пакет: Стандартний
Кількість учасників: 2 человека

Бажаний час: 14:00
⭐ Постійний клієнт: так
💰 Знижка: Постійний клієнт −10%: 4 500 грн → 4 050 грн
Спосіб зв'язку: Telegram — @username
Повідомлення: Хотіла б...

Дата заявки: 29.08.2026 14:32
```

## 🔄 Як оновлювати код з GitHub

Коли розробник пише новий код і пушить на GitHub, на сервері потрібно:

```bash
cd ~/my-lamp-project/src/n.franya.dev
./sync.sh
```

**Що робить `sync.sh`:**
1. Створює бекап `data/*.json` у `backup-data-<дата>/`
2. Скидає локальні зміни в `data/`
3. Робить `git pull origin main`
4. Відновлює `data/bookings.json` з бекапу (заявки клієнтів не втрачаються!)
5. Відновлює `data/admin.json` з бекапу (пароль не скидається!)
6. Виправляє права на `data/` та `uploads/`

**Що НЕ потрібно:**
- ❌ Перезапускати Docker (PHP-FPM має `opcache.validate_timestamps=1`)
- ❌ Перезбирати образ (тільки якщо не змінився `Dockerfile.php` або `nginx.conf`)

**Винятки коли треба перезавантажити Docker:**
- Змінився `docker-compose.yml` → `docker compose up -d`
- Змінився `docker/Dockerfile.php` → `docker compose up -d --build`
- Змінився `docker/nginx.conf` → `docker compose restart nginx`

## 🆘 Якщо щось зламалось

### Сайт не відкривається
```bash
docker compose ps          # чи запущені контейнери
docker compose logs nginx   # логи Nginx
docker compose logs php     # логи PHP
```

### Адмінка не відкривається (білий екран)
- Перевір `data/admin.json` — чи існує, чи не порожній
- Запусти `./fix-permissions.sh`

### Фото не завантажуються через адмінку
- Перевір права на `uploads/`: `ls -la uploads/`
- Запусти `./fix-permissions.sh`

### Заявки не приходять в Telegram
- Перевір що в адмінці → Налаштування → Telegram Bot заповнені Bot Token + Chat ID
- Натисни «📲 Надіслати тестове повідомлення»
- Перевір логи: `docker compose logs php | grep -i telegram`

### Git pull не працює (локальні зміни)
```bash
./sync.sh
```
Цей скрипт безпечно синхронізує з GitHub, зберігши заявки клієнтів.
